## Investigar qué existe para implementar: Argos compact desktop — ocultar columnas de baja prioridad en la tabla de posiciones

**Resumen:** La implementación de 'ocultar columnas de baja prioridad en compact' está completamente especificada en SPEC-compact-desktop-overview-redesign.md (Módulo M4) y gira en torno a un único componente vivo: src/features/portfolio/components/GroupedPositionsTable.jsx. Allí el array COLS define las 10 columnas y MIN_W fija el ancho mínimo de la tabla, por lo que hay que marcar pprom y diapct como priority:'low', aplicar compact:hidden a cada <th>/<td> (incluidas las filas de grupo y el tfoot) y exponer un MIN_W alternativo. El flag de reversibilidad src/config/layoutFlags.js (COMPACT_OVERVIEW_ENABLED) ya existe y debe usarse para ramificar className; el ordenamiento funciona por key de columna (no por índice), así que ocultar columnas no lo rompe. Falta confirmar el estado de tailwind.config.js respecto del breakpoint screens.compact.

### Patrones a seguir
- Definición declarativa de columnas vía array COLS con metadata por columna (key, label, minW, align, sortable, defaultDir) — el patrón natural para agregar priority: 'low' es extender cada objeto de COLS.
- Render de headers/celdas por map/orden fijo sobre COLS y por filas de <td> escritas manualmente en el mismo orden que COLS — ocultar columnas exige tocar TANTO headers como cada <td> (position rows, group rows y footer).
- Uso de clases Tailwind con variantes de breakpoint (md:, lg:) para responsive CSS-only; el patrón a seguir es agregar compact:hidden a los <th>/<td> de baja prioridad.
- Uso del flag de reversibilidad COMPACT_OVERVIEW_ENABLED importado desde src/config/layoutFlags.js para ramificar className (no reemplazar) — requisito no-negociable de la spec.
- Ancho mínimo de tabla fijado en JS vía style={{ minWidth: MIN_W }} donde MIN_W = suma de col.minW; para compact se requiere un MIN_W_COMPACT alternativo.
- Guard de montaje/props con defaultTypeOf/defaultStrategyOf exportados y reusados por otros componentes — cambiar COLS no debe romper esos exports.

### Riesgos / Restricciones
- Las filas de <td> están escritas manualmente en orden idéntico a COLS, incluidos group headers y tfoot (celdas vacías con [0,1,2].map). Ocultar columns solo en COLS sin tocar cada <td> desalinea header vs celdas.
- MIN_W se usa como style minWidth inline en <table>; ocultar columnas por CSS deja el minWidth en ~995px y el scroll horizontal persiste — se necesita un MIN_W_COMPACT calculado en JS.
- El sort usa getSortValue(pos, key) mapeado por string de key (no por índice), por lo que columnas ocultas no rompen el ordenamiento; pero handleSort hace COLS.find(c => c.key === key) → si se quitan entradas de COLS sí se rompería.
- El componente se exporta por default como PositionsTable (naming histórico) aunque el archivo sea GroupedPositionsTable.jsx — no confundir con el PositionsTable legacy eliminado.
- MobilePositionsList y componentes strategy (RebalanceAlerts, TargetAllocation) importan símbolos desde este archivo (defaultTypeOf/defaultStrategyOf y grupos); cualquier refactor debe preservar esos exports.
- Debe respetarse la máscara de saldos (MoneyValue / useBalanceVisibility): P. Prom. usa MoneyValue, así que ocultarla por breakpoint no debe alterar el toggle de visibilidad en el tier full.
- layoutFlags.js ya existe con COMPACT_OVERVIEW_ENABLED = true; el implementador debe ramificar sobre ese flag, no introducir otro mecanismo de toggle.
