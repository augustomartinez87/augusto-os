## Contexto

En `app/dashboard/simulator/page.tsx`, las dos mutations de creación solo cierran el modal y limpian
el nombre (líneas ~319-333):

```tsx
const createLoanMutation = trpc.loans.create.useMutation({
  onSuccess: () => {
    setCreateLoanOpen(false)
    setBorrowerName('')
  },
})

const preApproveMutation = trpc.loans.createPreApproved.useMutation({
  onSuccess: () => {
    setCreateLoanOpen(false)
    setBorrowerName('')
    setIsPreApprove(false)
  },
})
```

Hay un mensaje de éxito escrito (líneas ~898-902):

```tsx
{(createLoanMutation.isSuccess || preApproveMutation.isSuccess) && (
  <p className="text-sm text-accent-positive">
    {isPreApprove ? 'Préstamo preaprobado guardado' : 'Préstamo creado exitosamente'}
  </p>
)}
```

pero **es código muerto en la práctica**: vive dentro del `<form>` del modal, y `onSuccess` hace
`setCreateLoanOpen(false)` justo antes, así que el modal se desmonta y nadie llega a verlo. El
usuario toca "Crear Préstamo", el modal desaparece, y no queda ninguna señal de si funcionó. Encima
`setIsPreApprove(false)` corre antes del render, así que aunque se viera, el texto podría mostrar la
variante equivocada.

La infraestructura para hacerlo bien ya está en el repo, no hay que instalar nada:
`hooks/use-toast.ts` exporta `useToast` y `toast` (línea 194), y `<Toaster />` ya está montado en
`app/layout.tsx` (línea 42). La ruta destino existe: `app/dashboard/loans`.

## Pasos sugeridos (el planner puede refinar)

1. Importar `useToast` (o `toast`) desde `@/hooks/use-toast` y `useRouter` desde `next/navigation`
   en `app/dashboard/simulator/page.tsx`. Revisar primero si el archivo ya importa alguno de los dos
   para no duplicar.
2. Capturar el nombre del prestatario ANTES de limpiarlo, para poder usarlo en el texto del toast —
   `setBorrowerName('')` corre en el mismo `onSuccess`, así que leer el estado después ya devuelve
   vacío. Usar el argumento `variables` del callback de la mutation, o guardar el valor en una
   const al inicio del handler.
3. En `createLoanMutation.onSuccess`: disparar el toast de creación, cerrar el modal, limpiar el
   nombre y navegar a `/dashboard/loans` con `router.push`.
4. En `preApproveMutation.onSuccess`: lo mismo pero con el texto de preaprobación, manteniendo el
   `setIsPreApprove(false)` que ya está.
5. Eliminar el bloque de mensaje de éxito inline (líneas ~898-902) que quedó inalcanzable. Dejar
   intacto el bloque de error (líneas ~895-897): ese sí se ve, porque en error el modal no se cierra.
6. Revisar el `disabled` del botón submit (línea ~906): hoy incluye `isSuccess` para evitar doble
   envío. Con el redirect eso pasa a ser irrelevante, pero **no sacarlo** — protege la ventana entre
   el éxito y la navegación efectiva.
7. Agregar/extender tests que cubran: (a) éxito de creación dispara toast y navegación;
   (b) éxito de preaprobación dispara el texto distinto; (c) error no navega ni muestra éxito.
   Seguir el patrón de tests del proyecto para mockear `next/navigation` y el hook de toast.
8. Correr typecheck, lint y tests, y corregir lo que rompa.

## Fuera de alcance

- Rediseñar el modal de creación o el formulario del simulador.
- Resaltar o hacer scroll hasta el préstamo recién creado dentro de `/dashboard/loans`.
- Tocar los routers `loans.create` / `loans.createPreApproved` — el problema es 100% de frontend.
- Cambiar el comportamiento de error más allá de garantizar que no navegue.

## Restricciones clave

- Sin migración de schema ni cambios en la base.
- Usar el sistema de toasts que ya está en el repo (`hooks/use-toast` + `<Toaster/>` en el layout).
  NO agregar `sonner` ni otra librería de notificaciones.
- La TNA/tasa NUNCA debe mostrarse en vistas de prestatario — el toast no debe incluir tasa ni TNA,
  solo el nombre y qué se creó.
- El redirect no puede tragarse un error: si la mutation falla, el usuario tiene que quedar donde
  estaba, con sus datos.
