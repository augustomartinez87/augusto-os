## Contexto

Hallazgo de la revisión posterior al release de F-0092 (2026-10-08), verificado ejecutando la función real de `lib/payment-amount.ts` (copia idéntica en un directorio temporal, fuera del repo) sobre un barrido de centavos: de 899 casos probados (enteros representativos × centavos 01–99), **39 se interpretan con un centavo menos**. Ejemplos reales: `'0,29'` → 0.28, `'0,57'` → 0.56, `'1.234,09'` → 1234.08, `'165.000,02'` → 165000.01, `'165.000,05'` → 165000.04.

Causa (verificada en el código): se hace `parseFloat('165000.05')` → 165000.05 (que en binario es 165000.04999…) y luego `Math.trunc(n * 100) / 100` → `Math.trunc(16500004.999…)` = 16500004 → 165000.04. La intención de ADR-0280 (truncar para no cobrar de más) es correcta, pero la implementación es insegura con coma flotante. Los tests de F-0092 usaron pocos valores y no lo detectaron; además los "mutantes" de `tests/f0092-mutation.test.ts` son copias locales de la función, no el código real.

Impacto: el usuario tipea un cobro con centavos (por ejemplo los $165.000,05 de una cuota) y el sistema registra un centavo menos; en el botón de confirmar se vería "$ 165.000,04", pero el error es silencioso si no se lee con atención. Está en producción desde el release de F-0092 (commit db0e26c).
