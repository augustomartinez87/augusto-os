## Contexto

Ya existe `src/components/ui/Sparkline.jsx` — componente genérico (`AreaChart` de Recharts sin
ejes/tooltip/dots, recibe `data: number[]`, `color`, `height`, `showActiveDot`), usado hoy en
Portfolio (`MobilePositionsList.jsx`, ver AR-016/AR-021 en el historial). **Reusar este componente
tal cual** — no crear uno nuevo. El patrón de reserva de espacio cuando no hay data (`div w-[72px]
h-[28px]` vacío) usado en `MobilePositionsList.jsx` (ver AR-021 en el historial) es el mismo patrón
a seguir acá para fondos sin suficiente historial.

La fuente de datos es `fci_prices.vcp` — ya existe `mercadoService.getPricesBatch(fciIds, fromDate)`
que trae precios para múltiples fondos de una sola query agrupada por `fci_id`. Con paginación de
50 filas por página, una llamada a `getPricesBatch` con los 50 `id` de la página actual y
`fromDate = subtractDays(35)` (margen sobre 30 para no perder por fines de semana/feriados) alcanza
— no hace falta traer todo el universo.

`font-variant-numeric: tabular-nums` es una propiedad CSS estándar, no requiere librería.

## Pasos sugeridos (el planner puede refinar)

1. Agregar una columna nueva "Tendencia" (o similar) a la tabla en `FciExplorador.jsx`.
2. En `loadPage` (o un efecto aparte que dispare después), llamar a
   `mercadoService.getPricesBatch(idsDeLaPaginaActual, subtractDays(35))` y mapear cada fondo a su
   array de `vcp` ordenado por fecha.
3. Renderizar `<Sparkline data={vcps} color={...} height={28} />` por fila; si el fondo tiene menos
   de 2 puntos, `Sparkline` ya devuelve `null` — envolver en un contenedor de tamaño fijo para que
   el layout no salte (mismo patrón que `MobilePositionsList.jsx`).
4. Elegir el color del sparkline consistente con el signo del período relevante (ej. mismo criterio
   de color profit/loss que ya usan `pctCell`/`tnaCell` en este archivo) o un color neutro fijo si
   mezclar semántica de color complica más de lo que aporta — decisión del planner, documentar cuál
   se eligió.
5. Aplicar `font-variant-numeric: tabular-nums` (clase Tailwind `tabular-nums` si el proyecto tiene
   esa utilidad habilitada, si no, la propiedad CSS directa) a las celdas de 1D/7D/30D/YTD/1Y/TNA.
6. Confirmar que la tabla sigue scrolleando horizontal en mobile sin que el sparkline la rompa.
7. Tests + typecheck.

## Fuera de alcance

- Cambiar `Sparkline.jsx` — se consume tal cual, cualquier ajuste ahí podría afectar Portfolio.
- Sparklines en el Comparador — este feature es solo del Explorador.

## Restricciones clave

- No crear un componente de sparkline nuevo — reusar `src/components/ui/Sparkline.jsx`.
- El fetch de precios para el sparkline debe acotarse a los fondos de la página actual visible, no
  al universo completo (evitar traer miles de series de precios de una sola vez).
