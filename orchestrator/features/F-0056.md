## Contexto

**Verificado por Cowork, 2026-09-10, revisando el diff real de F-0054 (`git diff` contra el commit anterior) y el
schema real de Supabase (`information_schema.columns`), no solo confiando en que el log del orquestador dijo
RELEASED** -- F-0054 (aplicar rescates de FCI detectados automaticamente) quedo pusheado a prod con un bug que hace
que la funcionalidad nueva (boton "Aplicar" en la UI) **nunca funcione con datos reales**.

`applyPendingRescate(rescateId, method)`, en `src/features/fci/services/fciService.js`, lee la fila completa de
`fci_rescates` (`select('*')`) y le pasa `rescate.tipo` como parametro `tipo` a la funcion interna `_consumeLots`,
que lo usa para filtrar `fci_lots`:

```js
const result = await _consumeLots(
    rescate.portfolio_id,
    rescate.fci_id,
    rescate.cuotapartes,
    rescate.vcp_salida,
    rescate.tipo,   // <-- fci_rescates NO tiene columna `tipo`
    method
);
```

Confirmado contra el schema real (`select column_name from information_schema.columns where table_name =
'fci_rescates'`): la tabla tiene `id, user_id, portfolio_id, fci_id, fecha_rescate, cuotapartes, vcp_salida,
monto_rescatado, mutations, notes, created_at, external_ref` -- **no hay columna `tipo`**. Por lo tanto
`rescate.tipo` es siempre `undefined` en produccion.

`_consumeLots` usa ese valor para `.eq('tipo', tipo)` contra `fci_lots`, que si tiene columna `tipo` (valores reales
en prod: `'portfolio'` o `'carry'`, nunca null -- verificado con `select distinct tipo, count(*) from fci_lots`).
Filtrar por `tipo = undefined` no matchea ningun lote real, asi que `activeLots` siempre sale vacio, y tanto el
camino PPC como el FIFO tiran error antes de tocar ningun dato (fail-safe, no corrompe nada, pero la funcionalidad
completa de F-0054 queda inutilizable).

**El propio orquestador ya habia marcado esto como sospechoso y nadie lo reviso:** el log de F-0054 genero
`ADR-0137 -- \`tipo\` leido desde fci_rescates (columna de F-0053) [Supuesto del agente] <- REVISAR` -- el executor
asumio que esa columna existia (quizas confundiendola con `fci_lots.tipo`), lo marco explicitamente para revision
humana, y el reviewer (LLM) lo aprobo igual sin verificar contra el schema real.

**El test nuevo de F-0054 no detecto el bug** porque su fixture `PENDING_RESCATE` en
`fciService.pendingRescates.test.js` incluye a mano `tipo: 'portfolio'` (un campo que la fila real de la tabla
nunca va a tener), y el mock de Supabase (`makeChain`) encadena `.eq()` sin validar que valor se le paso -- el test
pasa igual si `tipo` es `'portfolio'` o `undefined`.

**Por que no exploto todavia:** verificado contra Supabase real -- hoy no hay ninguna fila en `fci_rescates` con
`external_ref` seteado y `mutations` vacio/null (`select ... where external_ref is not null and (mutations is null
or mutations = '[]')` devuelve 0 filas), y tampoco hay lotes en `fci_lots` con `external_ref` seteado. El sync
automatico de F-0053 corre los lunes 09:00 UTC -- la proxima corrida real es el lunes 14/9. Este fix deberia
mergearse antes de esa fecha o antes de que Augusto intente usar el boton "Aplicar" manualmente, lo que pase
primero.
