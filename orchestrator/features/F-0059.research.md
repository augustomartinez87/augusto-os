### Riesgos / Restricciones
- tailwind.config.js usa sintaxis ESM (`export default`, `plugins: []`) mientras la SPEC propone `...require('tailwindcss/defaultTheme').screens` — `require` puede no estar disponible en un config ESM; probablemente hay que usar import (`import defaultTheme from 'tailwindcss/defaultTheme'`). [NO VERIFICADO: no confirmé el `type` de package.json ni cómo se carga el config]
- La SPEC indica agregar `screens` a nivel `theme` pero el archivo real solo tiene `theme.extend`; agregar `screens` fuera de `extend` o dentro cambia el comportamiento (reemplaza vs. extiende), riesgo de pisar breakpoints default.
- Orden de prefijos Tailwind `compact:md:` — el orden de las variantes en el string afecta el orden de las media queries generadas; requiere verificación.
- Estrategia CSS-only para el breakpoint de alto, pero M5 (sidebar default) necesita una lectura puntual de `matchMedia('(max-height: 820px)')` en el primer render, y debe respetar la persistencia de localStorage (`STORAGE_KEY`) para no pisar la preferencia del usuario.
- `MIN_W` en GroupedPositionsTable es un valor JS (no solo CSS), así que ocultar columnas con `compact:hidden` no reduce el `min-width` fijado en JS — la SPEC advierte que puede necesitar un `MIN_W_COMPACT` paralelo. [NO VERIFICADO: no leí cómo se consume MIN_W en el render]
- Invariantes a no romper: censura de saldos (`MoneyValue`/`useBalanceVisibility`/`HIDDEN`), tokens CSS (`--surface-*`, `--border`, `--teal`, `--ink*`), `isAnimationActive={false}` en recharts.
- Desktop full (≥820px alto) y mobile deben quedar pixel-idénticos; con `COMPACT_OVERVIEW_ENABLED = false` debe volver exactamente al comportamiento de stretch de hoy.
