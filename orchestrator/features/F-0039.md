## Contexto

En `src/features/portfolio/components/MobilePositionsList.jsx` el sparkline muestra los últimos ~8
cierres diarios (viene de `useSparklines` vía la prop `sparklineFor`, que baja desde
`src/pages/Dashboard.jsx:157`). O sea: es un gráfico de **ventana corta**.

Al lado, en el mismo renglón, se muestra `resultPct`, que es el **P&L acumulado desde la compra**.
Las dos cosas hablan de ventanas temporales distintas y el usuario las lee como si fueran la misma:
un sparkline que baja fuerte al lado de un `+180%` no comunica nada útil.

El dato correcto ya existe y ya se usa en este mismo archivo. En `PositionDetailSheet` (línea 50):

```jsx
const dailyPct  = currency === 'ARS' ? pos.dailyResultPct   : pos.dailyResultPctUSD;
```

y se muestra como fila propia "Día %" (línea 57). El fix es replicar ese mismo `dailyPct` en los dos
bloques de lista, que hoy solo calculan:

```jsx
const result    = currency === 'ARS' ? pos.result    : pos.resultUSD;
const resultPct = currency === 'ARS' ? pos.resultPct : pos.resultPctUSD;
```

El bloque a cambiar es idéntico en ambos lugares (líneas ~241-247 y ~371-377):

```jsx
<div className="flex items-center gap-1.5">
  {spark ? <MiniSpark data={spark} /> : <div className="w-[72px] h-[28px] flex-shrink-0" />}
  <span className="text-[11px] font-medium num" style={{ color: result >= 0 ? TEAL : CORAL }}>
    {result >= 0 ? '+' : ''}{formatNumber(resultPct || 0, 1)}%
  </span>
</div>
```

Ojo con el detalle del color: hoy el signo del color viene de `result` (monto absoluto acumulado) y
el número de `resultPct`. Van juntos por casualidad, no por diseño. Al pasar a diario hay que tomar
signo y número de la MISMA variable.

## Pasos sugeridos (el planner puede refinar)

1. En el bloque de `featuredPositions` (~línea 208-213), agregar el cálculo de `dailyPct` con
   exactamente el mismo patrón que la línea 50 (`currency === 'ARS' ? pos.dailyResultPct : pos.dailyResultPctUSD`).
   No borrar `result` ni `resultPct` todavía — se siguen usando en otros lugares del mismo botón.
2. En ese mismo bloque, cambiar el `<span>` pegado al `MiniSpark` para que use `dailyPct` como
   número Y como signo del color. Manejar el caso `dailyPct == null` mostrando `—` con el color de
   texto neutro del tema (usar la variable/clase de texto atenuado que ya usa el archivo, ej.
   `text-ink-faint`), sin inventar un color nuevo.
3. Repetir exactamente 1 y 2 en el bloque de la lista agrupada (`group.visibleItems`, ~línea 336-341
   para el cálculo y ~línea 371-377 para el render).
4. Revisar si `resultPct` o `result` quedaron sin uso en alguno de los dos bloques; si quedó alguna
   variable muerta, sacarla para que lint quede limpio.
5. Correr typecheck, lint y tests, y corregir lo que rompa.

## Fuera de alcance

- `PositionDetailSheet` (mismo archivo, líneas ~45-80): ya muestra "Día %" y "P&L %" como filas
  separadas y correctas. No tocar.
- Las tablas de desktop y cualquier otra vista de posiciones.
- Cambiar de dónde salen los sparklines o su cantidad de puntos (`useSparklines`).
- Agregar el P&L acumulado en otro lugar del renglón para "compensar" — el dato sigue disponible
  al abrir el detalle de la posición, con un tap.

## Restricciones clave

- Sin migración de schema ni cambios en Supabase — es exclusivamente presentación.
- Respetar las convenciones del skill `argos-theme` (auto-cargado) para tabla/censura/layout.
- Usar los tokens de color ya definidos en el archivo (`TEAL`, `CORAL`) y las clases de texto
  existentes. No introducir colores hardcodeados nuevos.
- Los dos bloques de lista deben quedar idénticos entre sí — es el mismo componente visual
  duplicado, cualquier divergencia es un bug futuro.
