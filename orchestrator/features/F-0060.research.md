## Mapa del repo para el fix 'hero chart con alto propio' dentro del rediseño compact desktop del Overview: identificar estructura, archivos, patrones, dependencias y riesgos.

**Resumen:** El repo es una app React 18 + Vite + Tailwind 3 (portfolio tracker 'Argos') con features aisladas en src/features. El fix del 'cuadro muy grande' está especificado en SPEC-compact-desktop-overview-redesign.md y corresponde al módulo M2: darle alto propio al wrapper `desktopEl` de PortfolioHeroChart (`md:h-[300px]` full / `compact:md:h-[220px]` compact) y quitar el stretch del grid con `items-start`/`self-start`. Se debe preservar el patrón de revert por flag (rama ternaria), el uso de tokens CSS, la censura de saldos y el CSS-only (sin hooks de resize).

### Riesgos / Restricciones
- La infraestructura (M1) ya está puesta: `tailwind.config.js` define `screens.compact` y `layoutFlags.js` exporta `COMPACT_OVERVIEW_ENABLED = true`, pero el grep de 'compact' sobre `src/**/*.{js,jsx}` devolvió 0 matches → ningún componente consume aún el flag ni usa clases `compact:`. - Riesgo de pisotear mobile/desktop-full: `compact:` debe usarse solo combinado con `md:`/`lg:`; nunca solo, para no afectar `md:hidden`.
- Revert con flag exige ramas if/ternario (más código) en cada componente; una implementación directa de clases haría el revert no trivial.
- Con `COMPACT_OVERVIEW_ENABLED = false` debe volver al comportamiento de stretch de hoy: caso a verificar explícitamente, no asumir.
- El cálculo de columnas de la tabla (`COLS`/`MIN_W`) puede consumirse en JS, no solo CSS; ocultar columnas con `compact:hidden` podría no alcanzar y requerir un `MIN_W_COMPACT` paralelo. [NO VERIFICADO la forma exacta de consumo]
- `useSidebarState` hoy deriva el estado inicial de `localStorage` ('sidebarExpanded'); M5 pide evaluar `matchMedia('(max-height: 820px)')` una sola vez al montar sin listener continuo.
- No se introducen breakpoints de ancho nuevos ni hooks de `window.innerHeight` con resize listener: mantener CSS puro.
