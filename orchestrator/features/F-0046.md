## Contexto

CAFCI no publica ningún campo que distinga clases para personas físicas vs. jurídicas — es una
convención comercial de cada gestora sin letra consistente. `fci_master` (3.974 filas activas) es
una fila por **clase**, no por fondo: los 3.974 `cafci_id` son todos distintos, coincidiendo con el
patrón de `estadisticas.cafci.org.ar/fondos/{fondo}?clase={clase}` donde el `cafci_id` guardado hoy
es el de la clase.

**Heurístico de agrupamiento (verificado contra la base real, 2026-09-07):**
`regexp_replace(nombre, '\s*-\s*Clase\s+[A-Za-z0-9]+\s*$', '', 'i')` agrupado junto con
`sociedad_gerente`. Contra los 3.974 fondos activos de hoy, 3.457 (87%) matchean el sufijo
"- Clase X" y agrupan limpio (conteo verificado por SQL directo contra `wwzocpcolgdzkvcigchj`); el
resto son fondos sin clases o con anotaciones tipo "(En proceso de liquidación)" — no forzar el
regex sobre esos, se quedan como grupo de 1 sola clase (ellos mismos).

**Criterio de clase por defecto:** dentro de cada grupo, la clase con `MIN(fecha)` más antigua en
`fci_prices` (o, equivalente, mayor `COUNT(*)` de precios). Es un proxy de patrimonio (que no existe
en el schema hoy — ver AR-030), pero es defendible: la clase más vieja de un fondo suele ser la
clase retail original. Validado contra Balanceado III: Clase A tiene 951 precios desde 2021-08-12,
Clase B recién 67 precios desde mayo 2026.

**Tabla de excepciones manuales `fci_class_overrides`:** arranca vacía o con los 4 casos ya
conocidos por Augusto (todos personas físicas, el heurístico de antigüedad se equivoca en estos 4):
Balanceado III Clase A, ICBC Capital Pesos, MMK USD Clase D, MegaQM Money Market USD Clase A. Se va
completando a mano por Augusto directamente en Supabase (SQL editor) a medida que aparecen
discrepancias nuevas — no bloquea el lanzamiento de este feature con la tabla vacía.

**Nota para una futura iteración (no implementar en este feature, no hay dato para confirmarlo
hoy):** el archivo `pb_get` que descarga `cafci_sync.py` tiene una columna 39, "Id Fondo CAFCI
padre" (`cafci_fondo_padre` en `scripts/cafci_inspect.py`), que por su nombre podría ser el ID de
fondo real que reemplazaría este heurístico por nombre — pero no se pudo verificar su tasa de
población porque el acceso a `api.pub.cafci.org.ar` está bloqueado por el proxy de esta red (403,
verificado al intentar correr `cafci_inspect.py` en vivo). Si en una corrida real del sync (que sí
tiene salida a internet vía GitHub Actions) esa columna viene poblada de forma consistente, vale la
pena reemplazar el regex por un join directo — pero eso es trabajo aparte, no de este feature.

**Migración a aplicar a mano ANTES de correr este feature** (igual que en F-0043 — el loop NO
la ejecuta, solo puede escribir/ajustar el archivo si hace falta):

```sql
-- supabase/migrations/039_fci_explorador_grupos.sql
-- Additive only.

CREATE TABLE IF NOT EXISTS public.fci_class_overrides (
  id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  fondo_base         TEXT NOT NULL,
  sociedad_gerente   TEXT NOT NULL,
  clase_preferida_id UUID NOT NULL REFERENCES public.fci_master(id) ON DELETE CASCADE,
  notes              TEXT,
  created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (fondo_base, sociedad_gerente)
);

ALTER TABLE public.fci_class_overrides ENABLE ROW LEVEL SECURITY;

CREATE POLICY "read_authenticated" ON public.fci_class_overrides
  FOR SELECT USING (auth.role() = 'authenticated');
-- Sin policy de escritura: se completa a mano por Augusto vía SQL editor
-- (service_role bypasea RLS), no desde la app.

CREATE OR REPLACE VIEW public.fci_explorador_grupos AS
WITH stats AS (
  SELECT fci_id, MIN(fecha) AS min_fecha, COUNT(*) AS n_precios
  FROM public.fci_prices
  GROUP BY fci_id
),
base AS (
  SELECT
    e.*,
    regexp_replace(e.nombre, '\s*-\s*Clase\s+[A-Za-z0-9]+\s*$', '', 'i') AS fondo_base,
    s.min_fecha,
    s.n_precios
  FROM public.fci_explorador e
  LEFT JOIN stats s ON s.fci_id = e.id
),
ranked AS (
  SELECT
    b.*,
    o.clase_preferida_id,
    ROW_NUMBER() OVER (
      PARTITION BY b.fondo_base, b.sociedad_gerente
      ORDER BY
        (o.clase_preferida_id IS NOT NULL AND o.clase_preferida_id = b.id) DESC,
        b.min_fecha ASC NULLS LAST,
        b.id
    ) AS rn
  FROM base b
  LEFT JOIN public.fci_class_overrides o
    ON o.fondo_base = b.fondo_base AND o.sociedad_gerente = b.sociedad_gerente
)
SELECT
  r.id, r.nombre, r.ticker, r.moneda, r.administradora, r.sociedad_gerente,
  r.clasificacion_cod, r.rend_1d, r.rend_7d, r.rend_30d, r.rend_ytd, r.rend_1y,
  r.tna, r.rend_updated_at, r.fondo_base,
  (SELECT COUNT(*) FROM ranked r2
     WHERE r2.fondo_base = r.fondo_base AND r2.sociedad_gerente = r.sociedad_gerente) AS n_clases,
  (SELECT jsonb_agg(jsonb_build_object('id', r3.id, 'nombre', r3.nombre, 'tna', r3.tna) ORDER BY r3.nombre)
     FROM ranked r3
     WHERE r3.fondo_base = r.fondo_base AND r3.sociedad_gerente = r.sociedad_gerente) AS clases_hermanas
FROM ranked r
WHERE r.rn = 1;

GRANT SELECT ON public.fci_explorador_grupos TO authenticated;

-- ROLLBACK:
--   DROP VIEW   IF EXISTS public.fci_explorador_grupos;
--   DROP TABLE  IF EXISTS public.fci_class_overrides;
```
